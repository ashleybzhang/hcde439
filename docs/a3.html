Assignment 3: Dusk-o-meter Night Light

A smart-home night light prototype: a photoresistor measures how bright the room is, and three LEDs fade up as the room gets darker.

1. Schematic and breadboard

2. Voltage divider calculations

The photoresistor is R1 (top) and the fixed resistor is R2 (bottom). A0 reads the voltage between them:

V_measure = 5 V × R2 / (R1 + R2)

My photoresistor goes from roughly 1 kΩ in bright light to 100 kΩ in the dark. A good fixed resistor is about the geometric mean of those two, so R2 = √(1 kΩ × 100 kΩ) ≈ 10 kΩ.

ConditionPhotoresistor (R1)CalculationV_measureanalogRead (V × 1023 / 5)
Very bright1 kΩ5 × 10 / (1 + 10)4.55 V≈ 931
Normal room10 kΩ5 × 10 / (10 + 10)2.50 V≈ 512
Dim50 kΩ5 × 10 / (50 + 10)0.83 V≈ 170
Dark100 kΩ5 × 10 / (100 + 10)0.45 V≈ 93

LED resistors

R = (V_source − V_forward) / I_target = (5 − 2.1) / 0.010 = 290Ω → 220Ω used

With 220Ω each yellow LED (forward voltage about 2.1 V) draws about (5 − 2.1) / 220 ≈ 13.2 mA, under the Uno's recommended 20 mA per pin. I went with 220Ω so the night light is a bit brighter.

4. Firmware

The sketch reads the divider with analogRead(), uses map() to turn that reading into a brightness (darker means brighter), and an if-statement decides whether the night light is on. The LEDs are driven with analogWrite().

// The analog pin that reads the voltage divider (V-measure)
const int SENSOR_PIN = A0;
// PWM pin for the first LED
const int LED_ONE = 9;
// PWM pin for the second LED
const int LED_TWO = 10;
// PWM pin for the third LED
const int LED_THREE = 11;
// Readings below this number mean the room is dark (about 1.5 V at the divider)
const int DARK_THRESHOLD = 300;

// setup() runs once when the Arduino powers up
void setup() {
  // Start the serial connection so I can watch readings on my computer
  Serial.begin(9600);
  // Set the first LED pin as an output
  pinMode(LED_ONE, OUTPUT);
  // Set the second LED pin as an output
  pinMode(LED_TWO, OUTPUT);
  // Set the third LED pin as an output
  pinMode(LED_THREE, OUTPUT);
}

// loop() runs over and over after setup() finishes
void loop() {
  // Read the voltage divider as a number from 0 to 1023
  int lightValue = analogRead(SENSOR_PIN);
  // Convert that reading back into volts (5 V is the Arduino's reference)
  float volts = lightValue * (5.0 / 1023.0);
  // Flip the range: my darkest reading (100) becomes full brightness (255), and the dark threshold (300) becomes off (0)
  int brightness = map(lightValue, 100, DARK_THRESHOLD, 255, 0);
  // map() does not stop at the ends, so keep brightness between 0 and 255
  brightness = constrain(brightness, 0, 255);

  // Check if the room is dark enough to need a night light
  if (lightValue < DARK_THRESHOLD) {
    // Set the first LED to the mapped brightness
    analogWrite(LED_ONE, brightness);
    // Set the second LED to the mapped brightness
    analogWrite(LED_TWO, brightness);
    // Set the third LED to the mapped brightness
    analogWrite(LED_THREE, brightness);
    // Print the label for the dark state
    Serial.print("Dusk-o-meter | NIGHT LIGHT ON  | light: ");
  } else {
    // Turn the first LED off
    analogWrite(LED_ONE, 0);
    // Turn the second LED off
    analogWrite(LED_TWO, 0);
    // Turn the third LED off
    analogWrite(LED_THREE, 0);
    // Report a brightness of 0 so the serial output matches the LEDs being off
    brightness = 0;
    // Print the label for the bright state
    Serial.print("Dusk-o-meter | daylight, lights off | light: ");
  }

  // Print the raw reading
  Serial.print(lightValue);
  // Print a separator and the voltage label
  Serial.print(" | volts: ");
  // Print the voltage with two decimal places
  Serial.print(volts, 2);
  // Print the label for brightness
  Serial.print(" | LED brightness: ");
  // Print the brightness value and end the line
  Serial.println(brightness);

  // Wait 200 ms so the serial monitor is readable and the readings are not jittery
  delay(200);
}

Why these values?

Value in codeWhat it corresponds to in the circuit
A0The node between the photoresistor and the 10 kΩ resistor (V-measure).
9, 10, 11The three LED branches. These are PWM pins, which analogWrite() needs.
map(..., 100, DARK_THRESHOLD, 255, 0)100 is the lowest reading I saw (about 0.49 V at the divider) and 300 is the threshold where the lights switch on. 255 is the max analogWrite() value. The output is reversed on purpose so darker means brighter LEDs, and ending the range at the threshold means the LEDs fade up from 0 instead of jumping on, which stops flickering when the reading hovers near 300.
DARK_THRESHOLD = 300About 1.5 V at the divider, which means the photoresistor is around 23 kΩ with my 10 kΩ resistor. That's about when a room starts to feel dim, so normal indoor light keeps the LEDs off.
delay(200)Five readings a second feels live without flooding the serial monitor.

5. Questions

Q1: Can the variable resistor be R1 or R2?

Either one works. Swapping them doesn't change how far the voltage can swing, it only flips the direction. With a 10 kΩ fixed resistor and a photoresistor that goes from 1 kΩ (bright) to 100 kΩ (dark):

SetupBright (1 kΩ)Dark (100 kΩ)
Photoresistor as R1 (top)
V = 5 × 10 / (R1 + 10)		5 × 10 / 11 = 4.55 V5 × 10 / 110 = 0.45 V
Photoresistor as R2 (bottom)
V = 5 × R2 / (10 + R2)		5 × 1 / 11 = 0.45 V5 × 100 / 110 = 4.55 V

With the sensor on top, more light means a higher voltage. On the bottom, more light means a lower voltage. I used the top so "more light = bigger number," but if I flipped it I'd just flip the map() output range and the if comparison.

Q3: 10-bit PWM and a 16-bit ADC

The map() numbers would need to change on both sides. A 16-bit ADC reads 0–65535 instead of 0–1023, and 10-bit PWM writes 0–1023 instead of 0–255. So map(lightValue, 100, 300, 255, 0) would become about map(lightValue, 6400, 19200, 1023, 0), since the input range scales up by 64 (65536 / 1024). The threshold of 300 would become about 19200 because it still means about 1.5 V.

The physical voltages stay the same, but the resolution improves. Each ADC step drops from about 4.9 mV to about 0.076 mV, and the LEDs get 1024 brightness levels instead of 256, so fades look smoother. map() uses long integers on Arduino, so the bigger numbers (65535 × 1023 is about 67 million) still fit without overflow.
